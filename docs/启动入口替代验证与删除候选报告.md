**当前没有任何一个 LEGACY 入口被 OFFICIAL 入口证明为完全替代。下一阶段真正允许删除的最小文件集合为空：`[]`。**

### 3.3 Ctrl+C／stop 与结果判定

| 入口 | 当前源码行为 | 不能扩大解释的边界 |
|---|---|---|
| 三机普通／多高度 | `trap cleanup EXIT INT TERM`；先停止 watchdog，再给 bag、launch PID 发 INT 并 wait；有 swarm.csv 时绘图；清理本脚本创建的 none 临时目录；保存进入 cleanup 时的状态 | 没有 `--stop`；不是降落命令；没有统一保证 INT 必为130；真实 recorder flush、PX4 结束和绘图本轮未运行 |
| 八扇区 | `--stop` 操作固定 tmux 会话；先等待 recorder，最多120秒，失败则保留会话；必要时 reindex active 并保留备份；再向其余窗口发 Ctrl+C，最多35秒后结束会话；有 CSV 时绘图 | 有特定录包保护流程，不能用简单 kill 替代；tmux detach 不停止任务 |
| waypoint | `--stop` 向固定会话窗口发 Ctrl+C，等待现有进程检查，最多35秒后结束该会话 | 与八扇区 stop 不等价，没有其 recorder 收尾流程 |
| Forest | `trap cleanup EXIT INT TERM` 对保存的 launch PID 发 INT 并 wait；正常退出后核对 summary：preflight 指定 verdict，其他 mode 要求 completed | INT 路径未显式统一退出130；summary 判定与 Worksite 不同；真实中断未验证 |
| Worksite | INT 显式退出130、TERM退出143，再由 EXIT cleanup 结束 log monitor 和 launch；正常路径返回 launch_status | 不校验 summary completed 后才返回0；必须独立读取 summary，不能把进程0当成训练完成 |

因此“都能用 Ctrl+C”不等于停止与结果语义完全相同。没有把任何旧脚本的停止逻辑替换为 OFFICIAL cleanup。
